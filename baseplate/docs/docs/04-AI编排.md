## 一、分层

```
AgentChatService        会话、SSE、落库、HITL / 外部调用恢复
AgentRuntimeFactory     按「Agent 配置 + pageKey + 工具集 + 技能集」构建 ReActAgent 并缓存
ToolRegistry            收集 AgentToolProvider；工具编码重名直接启动失败
ModelProviderFactory    OpenAI 兼容端点；配置从 agent_definition 读，密钥不回显
SkillIndexService       skills/<名称>/SKILL.md 扫描、索引、在线编辑
```

业务工具独立在 `baseplate-agent-workflow-starter`：Agent 平台只认 `AgentToolProvider` 接口，
不认识工作流和表单。

## 二、一次对话怎么走

1. 前端带 `pageKey` 调 `POST /api/agent/chat/stream`
2. `selectTools` 过滤：页面匹配 → 用户权限点 → Agent 绑定与审批策略
3. `AgentRuntimeFactory` 取缓存或构建 `ReActAgent`（系统提示词只剩角色与页面边界）
4. 事件流映射为 SSE：`text/thinking/tool_call/tool_result/skill/hitl/external_tool_call/ui/done`
5. 需要确认的工具停成 HITL；外部工具把参数下发前端，前端执行后回传结果再恢复
6. 每轮结束把消息与 blocks 落 `agent_message`，`ui` 卡片也写入历史块

## 三、工具分两类

| 类型 | 执行 | 例子 | 约束 |
|---|---|---|---|
| 内部工具 | 服务端 | `workflow_list_my_tasks`、`workflow_list_my_started`、`workflow_instance_progress`、`workflow_list_my_done`、`workflow_my_summary`、`workflow_task_detail`、`form_get_draft`、`platform_whoami` | 只读；代码里按权限点校验 |
| 外部工具 | 浏览器 | `workflow_get_canvas`、`workflow_create_draft`、`form_get_canvas`、`form_create_draft` | 前端带用户令牌调 REST，权限/审计/归属校验不绕过 |

**需要浏览器的写操作才做成外部工具**：创建草稿要打开设计器，只能前端执行。
同意/驳回/打回不做成工具——它们只是 REST 的一层包装，代签会让审批责任变模糊，
统一由用户在办理抽屉里确认。

## 四、页面作用域

- Agent 绑定的页面、工具声明的 `pages`、会话的 `page_key` 必须一致
- 继续旧会话时把 `session.page_key` 同步成当前页面，否则恢复流重建 Agent 时找不到工具
- 未绑定页面/权限的工具不会进模型上下文

## 五、UI 卡片

工具结果可带：

```json
{ "ui": { "kind": "task_list", "title": "我的待办", "tasks": [...] } }
{ "ui": { "kind": "workflow_preview", "title": "当前画布", "bpmnXml": "...", "route": "/workflow/designer" } }
```

服务端把它转成独立 `ui` 事件（字段用 `kind`，不能用 `type`），并从模型上下文剔除；
前端 `AgentAssistant.vue` 按 `kind` 渲染任务卡片或 bpmn-js 缩略图。
