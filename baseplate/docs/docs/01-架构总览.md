# 01 · 架构总览

## 形态

**模块化单体**：一个 Spring Boot 进程，包级隔离，不拆微服务。

边界不由 Maven 模块守护，而由 **ArchUnit 断言**守护。
理由：Maven 多模块会让本地开发多一个 install 步骤，收益却只是「看起来更专业」；
而「AI 包不许自己查库」这类规则，写进 ArchUnit 会在构建期红掉，写进文档会被人忘掉。

## 分层

```
com.cuntong
├── common/     最底层：响应包装、错误码、异常、脱敏、加密原语、配置
├── infra/      基础设施：JDBC、文件、事件、配额、幂等、分词、微信客户端
├── security/   鉴权与权限：JWT、拦截器、DataScope、审计切面、号码门面
├── biz/        业务模块（每模块 api / impl / repo / dto 四层）
├── ai/         AI 编排：配置、模型工厂、网关门面、合规过滤
└── web/        入口层：auth / common / miniapp / admin / ai
```

依赖方向：`web → ai → biz → security → infra → common`，**不反向**。

## 依赖规则（8 条，违反即构建失败）

| # | 规则 | 守的是什么 |
| --- | --- | --- |
| 1 | `ai` 不得依赖 `JdbcTemplate` / `DataSource` / `EntityManager` | AI 只能通过 Service 取数 |
| 2 | `ai` 只能依赖 `biz.*.api` 与 `biz.*.dto` | 再收一道，堵住 Repository 后门 |
| 3 | `web` 不被任何包依赖 | 业务逻辑不许漏进 Controller |
| 4 | `biz` 模块之间不互相依赖 `repo` | 将来拆服务时，api 就是现成切口 |
| 5 | 任何包不得依赖 `biz.*.impl` | 面向接口 |
| 6 | `common` 不依赖其他任何业务包 | 防止 common 变成垃圾桶 |
| 7 | 只有 `security` 能引用 `PhoneCipher` / `HashUtil` | 号码处理只有一处 |
| 8 | Controller 不得直接依赖 `Repository` | 同规则 3 的另一面 |

第 1、2 条是全套规则的核心。它们防的故障是：
**两个入口给不同答案**（「列表说接单中，AI 说暂停接单」）。
设计文档 6.5 认为这类故障「比答不出来严重十倍」，且偶发、难复现，
所以只能靠结构防，不能靠测试抓。

> 规则 7、8 是本文档新增的，不在设计文档 2.2 的六条里。
> 加它们的理由写在 `ArchitectureRulesTest` 的注释里。

## 用到的设计模式（按「解决什么问题」归类，不按名词堆砌）

| 模式 | 落点 | 解决的问题 |
| --- | --- | --- |
| 门面（Facade） | `PhoneService`、`ModelGateway`、`AiFacade`、`AdminService` | 把「这类事只有一个入口」变成代码事实，而不是约定 |
| 工厂 + 策略 | `ModelProviderFactory` | 换厂商不改调用方；按档位选模型 |
| 规约（Specification） | `NoticeVisibility`、`ContactVisibility` | 可见范围判定只有一处，AI 与页面共享 |
| 责任链 / 管道 | `EventHandler` 按类型分派 | 新增事件类型 = 新增一个类，不改轮询器 |
| 切面（AOP） | `@Audited` | 审计不能靠手写——手写会漏异常分支 |
| 拦截器 | `AuthInterceptor` | traceId 注入、token 解析、角色校验集中一处 |
| 模板方法 | `AiStage`（P0-c） | 各段只管自己的逻辑，超时/降级由管道统一处理 |

## 容量测算（为什么单实例够）

按一个 1200 人行政村：注册 500、DAU ≈75、公告年 110 条、三年库 <500 MB。
日常 QPS ≈0.007，发公告后的瞬时峰值 5–10。

所以工程重点不是扩容，是三件事：**限流**、**慢查询防护**、**AI 调用的超时与降级**。

## 部署形态

| 形态 | 适用 | 迁移成本 |
| --- | --- | --- |
| A · 村级单机 | 1–3 村试点 | — |
| B · 镇级集中 | 10–30 村 | **只改配置**（DB/Redis/OSS 地址） |
| C · 县级 + 私有化模型 | 50+ 村或数据不出县 | 模型网关加一个实现，改配置指向内网 |

A→B 不用改代码的技术依据：`village_id` 从第一天就在表结构里。
