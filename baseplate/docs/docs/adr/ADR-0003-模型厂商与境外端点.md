# ADR-0003 · 模型厂商与境外端点（**偏离设计文档**）

- 状态：已接受（2026-09-30），**含合规风险，需要持续复核**
- 决策人：用户（要求「都要：DashScope + OpenAI + Anthropic 三实现」）

## 与设计文档的冲突

《村通_后端开发设计文档 v1.0》第 7.6 节：

> **只接国内厂商**。网关里注册的实现均为国内厂商；不配置任何境外端点。
> 这是硬选择不是偏好。

用户要求三厂商全实现，其中包含 Anthropic（境外）。这条红线被破了。

## 决策

三实现都写，但**默认不放行 Anthropic**：

```
cuntong.ai.provider=dashscope              # 默认国内厂商
cuntong.ai.allow-overseas-endpoint=false   # 默认关闭
```

- `allow-overseas-endpoint=false` 时，`ModelProviderFactory` 不会装配 Anthropic 实例，
  启动打 WARN，取用时抛 `IllegalStateException`。
- 设为 `true` 才会装配。这个开关的语义是：**有人显式确认过数据出境这件事**。

## 为什么这样做而不是直接拒绝或照单全收

直接实现三家而不设开关，等于把「境外端点」变成默认可达路径——
现实里一定有人图省事配上 Key 就用，然后没人记得这回事。
加一个默认关闭的开关，成本是一行配置，换来的是「这件事被显式考虑过一次」。

## 残留风险（必须由部署方承担，代码挡不住）

1. **数据出境合规责任**。村民的问题文本、村里的公告内容会送到境外服务商。
   这一点代码无法判断，必须由部署方（村委会 / 乡镇 / 县级）确认并留存凭证。
2. **「不用于训练」的条款**。设计文档 7.6 要求厂商条款明确这一点并上传凭证。
   Anthropic 侧是否接受该条款、条款文本是什么，**本轮没有核实**。
3. **日志留存**。境外厂商侧的日志保留多久、是否可被第三方调取，未核实。

> 这三条没有一条是技术能解决的。把它们写在这里，是为了让「没人问过这个问题」
> 这个状态不成立。

## 私有化路径

`cuntong.ai.provider=openai` + `openai.base-url` 指向内网 vLLM 即可。
这是文档 10.4 里说的形态 C，也是唯一正当的私有化理由：「数据不出域」，不是省钱。

- [ ] 记录一次出境评估的结论与责任人
