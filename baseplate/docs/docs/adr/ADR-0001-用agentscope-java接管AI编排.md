# ADR-0001 · 用 agentscope-java 接管 AI 编排

- 状态：**已接受**（2026-09-30）
- 决策人：用户
- 影响范围：`com.cuntong.ai` 包、模型依赖、合规边界

## 背景

《村通_后端开发设计文档 v1.0》第 1.3 节决策 5、第 6.11 节的原文是：

> 自研薄网关（ModelGateway 接口 + 多实现）。**不引重框架**。
> 也不引 LangChain4j 之类做编排 —— 路由与合规拦截必须是自己的确定性代码，
> 交给框架黑盒就没法写回归断言。

用户明确要求：**AI 对接的框架用 agentscope-java 最新版本**。这推翻了上述决策。

## 决策

采用 agentscope-java **2.0.3**，由它的 Agent 编排接管。

落地形态：

| 层次 | 谁负责 | 说明 |
| --- | --- | --- |
| 协议适配 | agentscope-java | `DashScopeChatModel` / `OpenAIChatModel` / `AnthropicChatModel`，三家都是官方扩展模块 |
| 模型选择 | `ModelProviderFactory` | 按档位（LITE / STANDARD / FLAGSHIP）取模型实例并缓存复用 |
| 调用与降级 | `ModelGateway` | 超时即降级、不重试；每次调用记 token；异常不外抛 |
| 合规拦截 | `ComplianceFilter` | **确定性代码，不交给框架**（见下） |
| 取数 | `AiFacade` → `biz.*.api` | ArchUnit 强制 |

## 为什么这样切

引入框架省掉的是「HTTP 协议适配」这一层，那本来就是重复劳动。
但有两件事**不能**交给框架，交出去就会失去可测性：

1. **合规拦截**。设计文档 6.8 写得很明确：「提示词不是安全边界」。
   健康类改道、承诺性表述替换、refs 为空拒答——这三条必须是确定性代码并且能写断言。
   所以 `ComplianceFilter` 是普通 Java 类，没有任何框架参与，
   `ComplianceFilterTest` 里 5 条断言覆盖了它。
2. **取数路径**。AI 只能走 `biz.*.api` 的 Service，这条由 ArchUnit 断言（规则 1、2）物理保证。
   框架接管编排之后，这一点更危险而不是更安全——Agent 自己决定调什么工具，
   所以工具（Handler）也必须只能调 Service。

## 代价与风险（诚实记录）

- **降级链的表达力变弱**。设计文档 6.14 的五级降级链原本是「自研管道」里逐段跳过的。
  交给框架之后，「跳过生成段」这类操作要靠框架提供的钩子实现，
  本轮（P0-b）**尚未实现**，只在 `AiFacade` 里保留了能独立工作的降级路径。
- **回归断言的写法待定**。设计文档 6.16 要求意图准确率 ≥92% 进 CI。
  框架接管后这一套怎么跑，是 P0-c 必须回答的问题，**本轮没有答案**。
- **框架版本风险**。agentscope-java 2.0.x 仍在快速迭代（2.0.0 到 2.0.3 只用了不到 4 个月），
  API 存在变动可能。缓解措施：所有调用收在 `ModelGateway` 一个类里，
  换版本只改这一个文件。

## 本轮实际做了什么

P0-b 只落地了：三厂商模型装配（`ModelProviderFactory`）、带超时的调用门面（`ModelGateway`）、
确定性合规过滤（`ComplianceFilter`）、以及一条**能独立工作的降级路径**（`AiFacade`）。

编排本身（ReActAgent + Toolkit、9 个意图 Handler、七段管道）属于 P0-c，本轮未做。
这符合设计文档 12.1 的分期，也符合它的硬检查点：
**把 AI 相关代码全部屏蔽掉，小程序必须仍然完整可用**。

## 后续决议（2026-09-30，同日）

P0-c 设计评审时，「Agent 编排管到哪一层」这个遗留风险被结掉，结论与本文档不同：

> **用户选 A：`ReActAgent` + `Toolkit` 全程接管编排，不是本文档推荐的「只接管 FALLBACK 兜底」。**

同时确定：**流式输出**（工具调用与状态串成进度）、**向量先由全文检索替代**。

三件事随之重新定义，详见 [`ADR-0005`](ADR-0005-Agent全程接管与流式事件协议.md)：
① 「意图集封闭」→「工具集封闭（10 个 Tool，写死代码）」；
② 降级链从「跳过某段」改为「Agent 能力降级」（返回内容与屏号不变）；
③ 总预算 3 秒 → 10 秒（`URGENT_HELP` 走旁路，保住 800ms）。

本文档第 1 节对「合规拦截必须是确定性代码、不交给框架」的判断**保持不变且仍然有效**——
`ComplianceFilter` 依然是普通 Java 类，不参与 Agent 循环，只在 PostProcess 段执行。
